# critical-review-fix-loop — 批判性 review 并修复迭代
## §1 触发、边界与 DO/DON'T

触发：批判性全量复核、double-check、独立质疑已完成结论。不触发：普通 review、测试或单次 bug 修复；普通审查见 `skill://code-review/`。

| DO | DON'T |
|---|---|
| 分架构/实现/配置三域独立取证，记录证据和正确/错误判定 | 复述前轮结论或只凭关键词判定问题 |
| 修复 agent 按文件隔离，编排者统一 scoped/full gates | 并发改同一文件，或让修复 agent 跑项目级验证 |
| 独立复核批判结论，标注 BLOCKED/ADAPTATION/APPROXIMATION | 把批判本身当事实，或把推测写成确定性 |
| 迭代到无 evidence-backed 新修复项且 gates 全绿 | 未收敛就交付，或以“已验证”跳过终审 |

## §2 执行验收

1. 批判：最多 3 个并发域；完成条件：每项有证据、判定、建议。
2. 修复：按文件边界分批；完成条件：变更清单与未决项齐全。
3. 反批判：复核工具伪影、语义误判、过度声称；完成条件：结论可独立复现。
4. 收敛：运行统一 gates；完成条件：无新修复项且所有风险有标签。

> 用于"确保无失真""double check 所有工作""用批判质疑的眼光全量校验"类请求。

## 触发条件
- 用户要求批判性全量校验 / double check / 质疑所有内容 / 确保无失真
- 已完成一轮常规审计后要求"再校验"
- 用户明确"批判校验的结果也要验证（可能有误）"

## 核心原则
1. **质疑一切**——不信任任何"已验证/正确/通过"结论——独立从源码/测试/文档重新取证
2. **验证批判本身**——批判 agents 的结论也可能错——独立复核批判
3. **证据优先**——代码行为、测试结果、文档为唯一事实源；推理必须标注 [INFERENCE]
4. **诚实标注**——BLOCKED（资源/运行时不可静态恢复）/ ADAPTATION（平台适配）/ APPROXIMATION——不可冒充确定性

## 流程

### 1. 批判（质疑一切）
- dispatch **3 个 task agent**（≤3 并发，省略 `agent=` 走 default）分域批判：
  - **架构/接口**：模块边界、接口契约、错误处理、依赖方向——质疑每个"设计合理"
  - **实现/测试**：代码行为 vs 测试覆盖、边界条件、并发安全、资源泄漏
  - **配置/部署/文档**：配置一致性、文档准确性、部署路径完整性
- 调度说明只写 agent role；不写模型名称或成本信息。
- 每 agent 任务：`独立核对（不复用前轮结论）+ 输出（质疑点+证据+判定：正确/错误+修复建议）`
- 指令禁止改代码（只读审查——需修正的列修复建议）

### 2. 修复（≤3 并发——分批）
- 按批判发现 dispatch 修复 agents（每 agent 一项——不同文件并行安全）
- 每 agent 只编辑分配文件（任务中给出明确文件清单），跳过 tests/formatters/linters 与项目级验证；中文输出改动文件清单与 unresolved 问题
- 验证由 orchestrator 统一执行：每批收齐后按改动范围运行一次 scoped gates；全部批次完成后运行最后一次 full gate，不做并发全量测试

### 3. 验证批判本身（关键——批判也可能错）
- 前轮批判结论**独立复核**（不因"批判过了"就接受）：
  - 工具伪影：grep/lint 误报、测试 flaky、版本混淆
  - 语义误判：认为"问题"实际是 deliberate 设计选择
  - 过度声称：标注"严重"实际无影响路径
- 新轮次质疑前轮"正确"项（round1 判通过——round4 推翻，实测发生过）
- **终审升级**：需要更强复核时，skill 不指定模型名称；要求用户说明 agent role，再按该 role 调度。

### 4. 迭代直至收敛
- 每轮都会发现新问题——迭代到一轮无新修复项
- 收敛判据：新一轮 review 无 evidence-backed 修复项 + orchestrator gates 全绿（含最终 full gate）+ 无未标注设计缺陷/失真

## 高频问题模式
|模式|例子|对策|
|---|---|---|
|测试不覆盖实际行为|mock 掩盖了真实 subprocess 行为|对比 mock 与真实路径|
|接口契约隐含|函数签名不含异常类型/超时语义|文档化或加断言|
|配置漂移|常量在多处定义、值不一致|单一事实源检查|
|错误处理空路径|except: pass / catch-all|grep 所有 except/catch|
|并发隐患|共享状态无锁/daemon thread 泄漏|线程安全审计|
|循环自证|文档引用代码注释，注释引用文档|独立验证每个来源|

## 输出
- 每轮：批判结论（正确/错误+证据）+ 修复清单（文件+改动，由 orchestrator 统一验证）
