# Oracle 咨询工作流

## 什么时候咨询（触发 + 调用纪律）

### 触发词
用户说「咨询 oracle」「问 oracle」「oracle review」「找验收」「架构权衡」「根因分析」「风险判断」时触发。

### 主动咨询四条件（Agent 主动发起时必须全部满足）
1. 已穷尽自身推理（2-3 种思路）
2. 是决策性的（trade-off，非格式/explore）
3. 不重复（之前没问过相同问题）
4. 上下文已就绪

### 禁止项
- 每步都问「下一步」
- 同题换说法反复问
- 用 full oracle 做 explore/格式审查
- 用户明确说「一次性」「one-shot」时走持久路径

## 路由决策树

| 场景 | 路由 | 说明 |
|------|------|------|
| 代码审查/文档质量/测试覆盖 | oracle-lite | 日常审查，够用且省 |
| 架构 trade-off | oracle | 需要权衡判断 |
| 同一问题多次修复失败 | oracle | 需要跳出当前思路 |
| 上线前风险评审 | oracle | 需要独立视角 |
| 跨领域问题（并发+网络+存储） | oracle | 需要综合判断 |
| 用户明确要求 full oracle | oracle | 无条件执行 |

**默认规则**：用户说「咨询 oracle」时默认 oracle-lite，除非用户明确说「用 full oracle」。

## 咨询前上下文收集

### 三步流程
1. **项目上下文**：读相关代码/文档/测试，收集现状
2. **历史记忆**：检查 memsearch/drafts 是否有相关历史
3. **拼装 prompt**：按标准模板组织

### 必覆盖五项
- 项目概要（一句话）
- 代码现状（关键文件/函数/状态）
- 问题描述（现象/根因/影响）
- 已尝试方案（做了什么、结果如何）
- 约束与风险（不能做什么、有什么风险）

## 标准 Prompt 模板

```
## 项目上下文
{项目概要，一句话}

## 当前问题
{问题描述，包含现象/根因/影响}

## 已知事实
{代码现状，关键文件/函数/状态}

## 未确认假设
{不确定的地方，需要 oracle 验证}

## 已尝试方案
{做了什么、结果如何、为什么失败}

## 约束与风险
{不能做什么、有什么风险}

## 期望输出
{需要 oracle 给出什么：决策/方案/风险评估/...}

注意：上下文不足先指出缺失项，不要猜。
```

## 追问技巧（内容层面）

### 追问类型
- **补证据**：「这个结论有代码证据吗？」
- **收敛方案**：「给我一个最小可行方案」
- **风险展开**：「这个方案的风险点在哪？」
- **反方审查**：「如果你是反对者，你会怎么说？」
- **拆 commit**：「这个改动可以拆成几个独立 commit？」

### 追问纪律
- 沿用同一实例，不重发全部上下文
- 增量发送：新证据 + 已落实建议 + 未落实原因
- 让 oracle 明确哪些旧结论仍成立、哪些需修改

## 成本优化

- explore 先行：用 scout/fast 模型先探索，再决定是否咨询
- 压缩上下文：只发相关代码，不发整个文件
- 非关键用 lite：日常审查用 oracle-lite，省 token
- 限制轮次：3-5 轮追问后收敛，避免无限循环

## 交付模式

- **默认持久**：park/revive，上下文跨轮保留
- **一次性**：仅用户显式要求「一次性」「one-shot」「新实例」时
- 所有 CLI 命令/降级/模型映射 → 见 `persist-oracle` skill
